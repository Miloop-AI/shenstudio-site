## 2. 确认的设计

视觉稿（白色版）：https://claude.ai/artifact/4aVdEghGcWXDrGJeQZtr2m

区块顺序：

1. 导航：logo（官方原版）、最新 / 财经脱口秀 / 硅谷C位 / 短视频 / 关于沈琛琛 / 合作，红色「订阅频道」按钮（链接带 `?sub_confirmation=1`，点开直接弹出订阅确认）。手机上导航变成一排可横向滑动的文字。
2. Banner：她的新 banner，缩进版心、圆角。手机用 YouTube 的手机安全区裁切（宽度 1546/2560 的中段）。
3. 最新一期：大缩图（可在页面内播放，见第 4 节）、栏目与期数、标题、嘉宾 · 日期 · 播放量、简介第一段、「观看本期」「订阅频道」。
4. 播出时间条：财经脱口秀「每周五 18:30 · 美西时间」（她频道简介里公开写明的时间）；硅谷C位「不定期更新」（创办人确认它不一定在周日播出，不写固定时间）；第三格是「订阅并打开小铃铛」。不显示推算出来的「下一期日期」，免得她停播或改期时网站写错、还要人手动改。
5. 每个栏目一个区块：栏目说明、「全部 N 期 →」、4 张缩图卡片（时长、标题、期数 · 日期 · 播放量）。某个栏目的影片不满一排时，补一张「订阅，新一期上线第一时间通知你」卡片（不写日期）。手机上卡片横向滑动。
6. 短视频：6 张直式卡片。
7. 关于主持人：照片、她频道简介里的自我介绍、15 年 / 千集 / 百位。
8. 合作与关注：合作邮箱，以及 YouTube、播客（Apple Podcasts、Spotify）、小红书、视频号、抖音。
9. 页尾：logo、标语、版权。

视觉规则：白底，近黑文字，灰色辅助文字，红色 `#C62828` 只用在观看和订阅按钮上，深青 `#0B4A5A` 只用在小标题上。字体 Noto Sans SC。断点仍是 820px。页面里仍然没有 JS。

## 3. 内容从哪里来、怎么自动更新

**自动（每 3 小时，沿用现有的 GitHub Actions + Vercel Deploy Hook）**

- 来源改成 **YouTube Data API v3**。API key 放在 Vercel 环境变量 `YOUTUBE_API_KEY`。
- 每次 build 读三个播放列表（财经脱口秀、硅谷C位、短视频）里的影片，再批量读影片详情（时长、播放量、发布时间、简介）。每次用量不到 10 units，每天 8 次，远低于每天 10,000 的免费额度。
- **栏目 = 她自己的播放列表。** 她上传时把影片放进哪个播放列表，网站就显示在哪个栏目，不需要手动标签。
- 最新一期 = 两个节目播放列表里发布时间最新的一支。
- **只显示公开（public）影片。** 私人、未公开、排程中的影片一律跳过；她公开之后，下一次自动更新就会出现。（2026-11-09 硅谷C位列表里已有一支私人影片，是排程中的第 3 期。）
- 只读设定档里列出的三个播放列表。「C想一刻」等其他播放列表不显示。
- 期数 = 公开影片在该播放列表里按发布时间排的序号（财经脱口秀目前 1–6 期，硅谷C位 1–2 期）。
- 日期一律换算成美西时间显示（API 给的是 UTC，例如硅谷C位第 2 期 UTC 是 11/2，美西是 11/1）。
- 标题清理：去掉标题尾部的「｜沈琛琛 x Shannon｜财经脱口秀」这类后缀，只留节目标题本身。
- 简介：取影片说明的第一段。
- **全程不需要人手**：GitHub Actions 每 3 小时触发一次 Vercel 部署。GitHub 会在仓库 60 天没有任何动静时暂停定时任务，所以工作流程每个月自动做一次「保活」提交（更新一个时间戳文件），定时任务就不会被暂停。

**不自动（写在设定档里，改了要手动更新）**

- 新文件 `src/site.json` 放：栏目设定（播放列表 ID、名称、说明、播出时间、常驻嘉宾）、合作邮箱、各平台账号与链接、关于主持人的文字。
- 小红书、视频号、抖音没有公开接口，只放账号名称，有主页链接就加链接。视频号没有网页版，只写「在微信搜索」。

**失败处理**

- 读不到 YouTube API（key 无效、网络问题、额度用完）时，build 直接失败，Vercel 继续显示上一个正常版本。现在是 Podbean 失败才会挡住 build，改版后换成 YouTube 失败才会挡住。
- Podbean 从 build 里完全移除。

## 4. 最新一期在页面内播放

用 `<iframe srcdoc>`：先显示缩图和播放键，点了才载入 YouTube 播放器（自动播放）。不需要 JS，也不会一打开页面就载入整个 YouTube 播放器。在网站上播放也计入 YouTube 的观看数。其他卡片都直接链接到 YouTube。

## 5. 图片

- 影片缩图直接引用 YouTube 的图片网址（`i.ytimg.com`），不转成 base64 内嵌。20 多张内嵌会让页面多出 1 MB 以上。
- logo 与 banner 仍按原规则内嵌为 base64。
- 新 banner 存到 `assets/banners/`，重做电脑与手机两个裁切，重做分享图 `public/og.jpg`。

## 6. SEO

- 沿用 `seoHead`。JSON-LD 的 `sameAs` 改成 `@dadaomedia` 和各平台链接。
- 收录开关不变：设定 `SITE_URL` 之前保持 `noindex`。

## 7. 要改的文件

- `scripts/build.mjs`：数据部分改用 YouTube API，移除 Podbean，产生新版面需要的所有区块。
- `src/index.template.html`：换成白色版的版面与 CSS。
- `src/site.json`（新）：栏目、平台账号、邮箱、关于文字。
- `assets/banners/`、`public/og.jpg`：换成新 banner。
- `CLAUDE.md`、两份 handoff 文档（中英同步）、`docs/next-steps.md`：更新被推翻的旧规则，包括「全站只有一个图片位置」「播客与影片混成一个列表」「米白纸张配色」「Podbean 失败才挡 build」。

## 8. 验证

- 本机用 API key 跑一次 build，检查读到的影片、期数、下一期日期是否正确。没有 key 时要给出清楚的错误讯息。
- 用 headless Chrome 截电脑与手机宽度各一张图检查。
- 推到 `youtube-redesign` 分支，在 Vercel 的预览网址确认后再合并到 `main`。

## 9. 需要项目负责人做的

1. **申请 YouTube Data API key**：Google Cloud Console → 新建项目 → 「API 和服务」启用 YouTube Data API v3 → 「凭证」建立 API 密钥 → 把密钥限制为只能调用 YouTube Data API v3。把 key 加到 Vercel 项目的环境变量 `YOUTUBE_API_KEY`（Production 和 Preview 都要），本机测试用的 key 放在 repo 根目录的 `.env.local`（会加进 `.gitignore`，不进 git）。
2. （可选）小红书、抖音的主页链接。
3. 正式的合作邮箱申请好后告诉我，改设定档即可。
